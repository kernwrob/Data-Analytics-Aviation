# Course evaluation information

Provided by the user on 13 October 2026. The text below is preserved as supplied; verify any later course updates on Moodle. The concept has eight evaluation criteria and a ten-minute slot. Its contribution to the final grade is not specified in this excerpt.

Evaluation of the project concept presentation
Presentation Outline:
- The presentations of the project concept will be on-site in Winterthur and take place at the beginning of the lectures (large classes) from week 10 onwards (3-4 groups per lecture, 10 min. per group).
- For the presentation, provide a slide set (PDF-Document) and upload it to Moodle (see link below).
- A link to the presentation dates/times is available on Moodle (same link as for the group registration).
- Note that the dates/times of the presentations will determined by the lecturer once the project groups are registered.
To be evaluated:
1. Structure & outline (Clear outline presented and followed? Logical flow with recognizable thread? Balanced weighting of parts? Title clear? Names of all students available?)
2. Background & problem (Context of the project clear? Problem convincingly motivated?)
3. Objective & research question (Clearly defined?)
4. Data (Source shown? Structure of the data explained?)
5. Methods (Methods appropriate for the research question? Correctly described and justified?)
6. Expected results (Plausible? Linked back to the research question?)
7. Language (Freely spoken?)
8. Quality of the presentation (Quality of graphics, tables & slides according to scientific standards?)

Evaluation of the final project (max. 22 points)
Minimum requirements (9 points)
The project must be a Data Analytics project, i.e., must include content of the Data Analytics module.
The project must integrate several topics presented in the module, at a minimum these are the following:
1. Data collection using Web Scraping and/or a Web API. The data must be collected by the group itself; ready-made datasets (e.g. from Kaggle) are not permitted as the primary data source.
2. Data preparation and integration: the project must combine data from at least two different sources (e.g. scraped data enriched with data from opendataswiss). The integration step (matching keys, joining, resolving inconsistencies, number of records lost/gained) must be documented.
3. Data storage in a SQLite database including SQL queries from within Python.
4. Rich non-graphical and graphical exploratory data analysis (EDA).
5. Modeling: use of either regression or classification. The research question must go beyond a standard prediction task (e.g. include a comparison between groups, regions, time periods, or data sources).
6. Model evaluation using suitable measures of fit (e.g. r-squared, RMSE, accuracy, recall, precision, ...).
7. Correct interpretation of model results and measures of fit.
8. Documentation of AI usage for creating the code and the presentation (the use of AI is not only allowed but desired), including the advantages and disadvantages you found and where something did not work with the help of AI.
9. Making the material (data, Jupyter notebooks, ...) available on Moodle.
Note: The topic will be formally approved by the lecturers at the presentation of the project concept on-site in Winterthur (week 10 onwards). If you are unsure whether your topic meets the requirements and can achieve the points for the overall project (see the details on Moodle), please contact the lecturers before you prepare the project concept. A short email with your topic and research question (2–3 sentences) is enough, and you will get an initial assessment. Overused standard topics (e.g. plain used-car or real-estate price prediction without an extended research question) will be graded lower on creativity.
Additional points, if the following criteria are met (max. 6 points)
1. Creativity of implementation (creative is anything not specified in the lessons and exercises).
2. Use of a PostgreSQL or similar database (no SQLite!) with, e.g. SQL joins and aggregations from within Python.
3. Integration and visualization of geographical data.
4. Use of a Chi-squared test, analysis of variance (ANOVA), or correlation analysis (each test must include a p-value).
5. Use of k-means clustering in addition to the regression or classification model.
6. Code on a publicly available GitHub repository (provide the GitHub project URL in the project presentation).
Project presentation in the form of a video recording (max. 7 points)
To be evaluated:
1. Structure & outline
2. Topic presentation (Topic clearly defined? How convincingly presented?)
3. Content (substance, depth, weighting of parts)
4. Language / auxiliary tools (Freely spoken?)
5. Quality of the presentation & slides
6. Reflection on AI usage: the presentation (slides and video) must include which AI tools were used and how, the advantages and disadvantages you found when using AI, and where something did not work with the help of AI.
7. Time keeping: length of presentation in minutes = number of students per group × 5 minutes.
Notes:
→ Use the slide set (PDF) as the basis for the presentation.
→ Show the Python code & live demos only if it improves the understanding of methods and results.
→ Do not just scroll through the code in the Jupyter notebooks without explaining the code and results.
→ AI is a tool, not a substitute for understanding. The evaluation focuses on your ability to explain and justify your data, methods, and results.
